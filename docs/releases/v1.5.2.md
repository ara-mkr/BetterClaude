BetterClaude 1.5.2 is a fix release for Claude's Settings window and the Code tab.

## Fixed

- **Settings opens where you are.** The gear in the Code tab now opens Claude's Settings right over the Code tab instead of jumping you back to chat. Close it and you're back in your session.
- **Settings is no longer hidden behind the CLI.** Opening Claude's Settings while the CLI tab is showing used to leave the terminal painted on top of it. The CLI (and the Code tab) now step aside while Settings is open and come back when it closes.
- **Settings is fully visible and centred.** The top of the Settings window, including its search box, used to sit under BetterClaude's title bar. It is now centred in the space below the title bar.
- **Less clutter in the Code tab.** A new session no longer prints the project's full folder path under "What should we build in …?".

## First launch

**macOS:** the builds are ad-hoc signed but not notarized (notarization needs Apple's paid Developer Program), so the first open of a downloaded copy shows *"BetterClaude not opened. Apple could not verify it."* That's Gatekeeper, not a broken file. Here's the one-time way past it:

1. Drag BetterClaude to `/Applications`, try to open it, and click **Done** on the dialog (don't move it to the trash).
2. Open **System Settings, Privacy & Security**, scroll to the Security section, and click **Open Anyway** next to the BetterClaude message. Authenticate, then click **Open**.
3. It opens normally from then on.

Terminal alternative: `xattr -cr /Applications/BetterClaude.app`

**Windows:** SmartScreen shows *"Windows protected your PC"* because the installer isn't signed by a recognized publisher yet. Click **More info**, then **Run anyway**. Windows updates in place from each new release. On macOS, download each new DMG by hand until the build gets a Developer ID certificate and notarization.
